# Project Caelum-EO: Storage Topology & Data Lifecycle Specification

**Repository Namespace:** `github.com/FranekJemiolo/Caelum-EO`  
**Storage Layers:** MinIO (Local) / AWS S3 (Cloud), PostGIS, Local Scratchpad

---

## 1. Storage Tiers Overview

Caelum-EO segments data assets across four decoupled storage layers to optimize network I/O, cache efficiency, and analytical query performance:

| Storage Tier | Technology | Purpose | Retention Policy | Data Format |
| :--- | :--- | :--- | :--- | :--- |
| **Tier 1: Object Store (Raw)** | MinIO / S3 (`caelum-raw`) | Downloaded or cached windowed GeoTIFFs | 30 days rolling | Cloud-Optimized GeoTIFF (`.tif`) |
| **Tier 2: Object Store (Interim)** | MinIO / S3 (`caelum-interim`) | Aligned 6-band multi-temporal tensor cubes | 14 days rolling | Serialized NumPy (`.npy`) / Zarr |
| **Tier 3: Object Store (Chips)** | MinIO / S3 (`caelum-chips`) | High-resolution RGB/NIR verification chips | Persistent | JPEG / PNG / GeoTIFF |
| **Tier 4: Spatial Database** | PostgreSQL 15 + PostGIS 3.3 | Vectorized polygons, metadata, provenance | Persistent | WGS 84 (`EPSG:4326`) Geometry |
| **Tier 5: Local Scratchpad** | `./data/cache/` (Local Host/Docker) | Ephemeral GDAL raster co-registration | Ephemeral (cleaned on run completion) | Temporary raster `.vrt` / `.tif` |

## 2. MinIO / S3 Bucket Architecture

### 2.1. Bucket: `caelum-raw`
- **Key Schema:** `raw/{collection}/{mgrs_tile}/{date}/{item_id}/{band}.tif`
- **Example:** `raw/SENTINEL-2/34UFB/2026-09-27/S2A_MSIL2A_20260927T100031_N0500_R122_T34UFB/B02.tif`
- **Access Pattern:** Write once on initial STAC ingestion window fetch; read during raster stack assembly.

### 2.2. Bucket: `caelum-interim`
- **Key Schema:** `interim/stacks/{geofence_id}/{t0_date}_{t1_date}_{item_id}.npy`
- **Example:** `interim/stacks/suwalki-gap/20260515_20260927_S2A_34UFB.npy`
- **Payload Shape:** `(2, 6, H, W)` float32 array normalized to `[0.0, 1.0]`.
- **Access Pattern:** Written by `src/etl/raster_processor.py`; consumed by `src/inference/prithvi_detector.py`.

### 2.3. Bucket: `caelum-chips`
- **Key Schema:** `chips/{detection_id}/chip_rgb.png`
- **Example:** `chips/a1b2c3d4-e5f6-47a8-b901-23456789abcd/chip_rgb.png`
- **Access Pattern:** Generated by `src/inference/vectorizer.py` when an anomaly is confirmed; loaded in Deck.gl inspection drawers.

## 3. Relational & Spatial Database Tier (PostGIS)

- Stores the structured intelligence records:
  - Vector polygon geometry (`EPSG:4326`)
  - Calculated physical area in square meters (`ST_Area(geometry::geography)`)
  - Model classification label and confidence score
  - Direct URI pointing to the visual chip in `caelum-chips`
  - Full STAC provenance JSONB metadata
